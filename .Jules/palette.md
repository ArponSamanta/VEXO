## 2026-03-01 - Interactive Elements Nesting & Focus Indicators
**Learning:** In product cards that support both click-to-navigate and quick actions (like adding to cart/wishlist), nesting interactive elements within an anchor element is an accessibility anti-pattern that triggers screen reader confusion. Additionally, when quick actions are visually hidden by default but appear on hover, standard keyboard users are locked out from using them unless focus-within triggers are set (`group-focus-within:opacity-100` / `group-focus-within:translate-y-0`) and the image/background link is bypassed (`tabIndex={-1}`).
**Action:** When designing feature grids with hover actions, ensure interactive elements are structurally sibling to links rather than children, use `tabIndex={-1}` on links that lead to the same destination as headings/buttons on the card to prevent keyboard redundancy, and expose hover panels via focus-within attributes.
